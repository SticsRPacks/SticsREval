# SticsREval (development version)

* New `gen_workspace_from_idestics()` function to build a STICS text workspace
  from data retrieved from the IDEStics API. The IDEStics credentials are read
  from the `IDESTICS_USERNAME` and `IDESTICS_PASSWORD` environment variables,
  or prompted for in an interactive session.

* New `plot_rrmse_comparison()` function to plot the rRMSE of the evaluated
  version against the reference version, one point per variable, coloured by
  regression status (#69).
* New `overview_heatmap()` function to show the status of every variable for
  every species in a single heatmap, as on the report's homepage.
* New `usm_ratio_heatmap()` function to show the RMSE ratio of the USM
  evaluation for each USM and variable, coloured according to the degraded
  and critical thresholds.
* The Quarto report generated by `render_report()` has been refactored and
  cleaned up (#68).
* `evaluate()` no longer writes one HTML scatter plot per degraded variable
  under `plots/<species>/`. It now saves, for each species with degraded
  variables, their observations and simulations to
  `data/<species>_degraded_vars.rds`, and the species pages of the report
  draw the scatter plots from it.

# SticsREval 0.1.1

* The rRMSE comparison plots are now shown in the HTML report (#66).
* The minimum number of observations criterion (`n_obs >= 10`) is now applied
  consistently across the global, species and USM evaluations (#65).

# SticsREval 0.1.0

* First tagged release.
* `evaluate()` runs the global, per-species and per-USM statistical
  evaluations of a STICS version against field observations and against a
  reference version.
* `balance_closure_test()` checks water and nitrogen balance closure for each
  USM.
* `gen_workspace_from_sms()` builds a STICS text workspace from a raw SMS
  repository, and `run_simulations()` runs STICS on it and saves the
  simulation and observation data as RDS files.
* `render_report()` renders the evaluation results as a browsable HTML
  dashboard.
* A Docker image bundling the package, its dependencies and the Quarto CLI is
  published on the GitHub Container Registry.
